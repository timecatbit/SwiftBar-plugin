# 维护约定

本目录是 OpenCodex SwiftBar Token 插件的唯一维护源。源码、配置、构建和测试工具均在仓库的 `opencodex/` 子目录维护；以下命令在本目录执行。

## 已确认的产品约定

- 主页模块管理使用 280pt 紧凑列表，外观/目录设置放底部侧栏，勾选必须清晰可见。
- 保持 360pt 主页；Summary 与范围筛选器对齐。
- 范围筛选使用点击展开的原生下拉框；其他分栏悬停在旁边展开。
- Summary 概览不可选中，不显示悬停提示，不铺深色高亮。客户端标题可点击展开；仅使用轻微悬停反馈。
- “允许折叠”默认开启，客户端保留费用/Token/状态，各模块独立展开，可同时展开多个；关闭显示全部明细，再开启恢复各自状态。刷新、重开面板、隐藏再启用模块均保留状态，折叠不影响统计。
- 更新数量只显示在下方“应用更新”行，不能再加顶部更新徽标。
- 侧栏按内容计算宽度，徽标文字居中，与箭头保留间距；同类文本共用对齐列。
- 当天图表从首次调用前的一小段零线开始，费用统计仍覆盖当天。
- Komari 侧栏只保留一个总标题；默认主页保留余额、账户额度与在线状态，允许用户关闭模块。
- 右键星星只放模块管理入口、自动检测和 SwiftBar 自身菜单。模块面板可连续多选，必须立即反馈勾选并排队保存，不能每次选择后关闭。
- 主面板和侧栏只在内容超出可见高度时滚动；空间充足时禁止双指滚动与回弹，折叠后不留旧滚动偏移。
- 玻璃使用系统 regular 材质，尊重深浅色和降低透明度；用户已确认接受深色背景导致的右缘折射。
- 账户/监控/更新侧栏打开即检查对应来源，5 秒内去重，后台完成立即刷新；布局重绘不能再次触发网络检查。
- 子菜单悬停展开延迟 80ms。新数据源独立接入，不要求 OpenCodex 必须安装；未定价/未配置不伪造为零。
- 首次安装自动检测并选择可接入的本机/已配置 API 来源；升级保留用户选择。手动“自动检测”先在悬停侧栏说明行为，开始检测后必须二次确认，列出将启用/取消的模块并明确会覆盖当前选择；默认取消，确认才替换。取消不得写入设置。检测不解析对话、不发网络请求、不输出密钥。
- 安装产物独立运行，不引用源码仓库；私有设置存于用户应用支持目录。
- 深浅色使用动态语义颜色；左右键菜单不能同时存在。
- OpenCodex 自动更新；其他三个应用只提示。不得把其他应用改成自动安装。

## 实现与验证

- 动作通过 `panel-action.json` → SwiftBar 刷新 → 白名单执行 → 回执传递。不要从原生面板直接运行插件脚本，以免触发 Documents/TCC 访问问题。
- 保存回执携带不含目录/凭据的显示偏好及版本号，旧数据刷新不能覆盖已保存的选择；连续点击按顺序应用，后台检查期间不能静默丢弃用户动作。
- 菜单展开期间不得重建范围下拉控件。只在跟踪结束后更新布局。
- 使用 `python3 scripts/check.py` 验证。改动 Swift 代码时运行 `scripts/build.py`。
- 界面改动安装后必须实际点击星星、打开受影响侧栏并查看截图，不能仅以编译通过作为视觉验证。
- 不通过 AppleScript 启动 SwiftBar 本体；这可能弹出“已运行”提示。刷新使用 SwiftBar URL scheme。
- 配置与凭据必须留在本机。不要提交 `config.local.sh`、运行缓存、日志、SQLite 数据或含私人用量的截图。
- 安装使用 `scripts/install.py`，保留备份与本机状态。不要复制工作聊天里的历史目录作为新的维护源。
